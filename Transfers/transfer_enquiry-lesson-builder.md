## The unified workflow (confirmed design)

```
Stage 1 — Dialogue
  Innes describes the enquiry (subject, topic, key question, length,
  outcomes, any specific content)

Stage 2 — MTP Generation
  Claude generates Medium Term Plan:
    - phase structure with subject-appropriate phase names
    - lesson sequence with LO per lesson
    - both outcomes (writing + enquiry)
    - differentiation (A/Y/O/D) for main subject skills

Stage 3 — Confirmation gate
  Innes reviews and approves (or edits)

Stage 4 — Build (science: teaching PPTXs only for now)
  - One PPTX per lesson using subject template
  - AI-generated images woven in throughout
  - Standard slides: cover, LO (3-panel), Learning Review
  - Variable slides: Claude decides per lesson based on lesson focus
  - Supporting resources: TBD per subject (define with Innes at build time)
```

## What Claude needs to do with the example PPTXs

When Innes uploads example science PPTXs, do ALL of the following before writing any build code:

1. **Unpack the PPTX** (`unzip example.pptx -d /tmp/example_unpacked/`)
2. **Catalogue every slide layout** — list all layouts in `ppt/slideLayouts/`, their names, dimensions, placeholder positions (with EMU coords), fonts, colours
3. **Identify which layouts map to which slide purposes** — cover, LO, I Do, We Do, You Do, subject-specific types
4. **Extract embedded images** — list all files in `ppt/media/`, identify KC wheel and any subject icon images
5. **Catalogue slide master styling** — background colour, border colour, font scheme, theme colours
6. **List every distinct slide type present** in the example deck — these become the available slide types for the builder
7. **Note what's fixed vs variable** — which elements are always the same (school logo, subject header, LO panel structure) vs which Claude fills in per lesson
8. **Note where images appear** — which layouts have image placeholders, where AI-generated images would slot in

Present a full catalogue to Innes before writing any build code. Get confirmation that the catalogue is correct.

## Image generation integration (key requirement)

Image generation must be **woven into the build pipeline**, not bolted on at the end. Design principles:

- Every lesson gets at least one AI-generated image, used purposefully (not decoratively)
- Science: diagrams, process illustrations, organism images, equipment visuals
- Images are generated during the build, saved locally, embedded in the PPTX
- Use the `image-generation` skill / DALL-E pipeline that already exists
- Image prompts are generated by Claude based on lesson content — specific, science-accurate, age-appropriate (Y4, 8–9 year olds)
- If image generation fails, the slide falls back to a placeholder with a clear label — build does not block

The existing `context_image` slide type in `writing-lesson-pptx` is a starting point but needs to be more integrated and used more pervasively.

## Subject-specific notes (science)

From the `enquiry-planner` SKILL.md, science disciplinary skills are:
1. Plan and Ask Questions — predictions, equipment selection
2. Test — fair tests, variables, sorting evidence
3. Observe and Measure — careful observations, measurements, data loggers
4. Record and Present — bar charts, tables, scientific reports
5. Conclude — conclusions, patterns, scientific language

Y4 science topics: Electricity, Sound, Classification of Animals, Muscular and Skeletal System, Materials/States of Matter

Standard slide types to expect (confirm against example):
- Cover
- LO (3-panel: WALT / TIB / ISB)
- Retrieval/recall starter (not grammar warm-up)
- Prediction slide
- Experiment/investigation setup
- Observation/results recording
- Conclusion
- Learning Review (speech bubbles)

"Supporting resources" for science — **ask Innes at build time** what he actually wants generated (candidates: word banks, recording sheets, vocabulary displays).
